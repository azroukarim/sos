# Enigma2 Cython Compiler - v4.8 (الدليل العربي)

نحوّل ملفات البلوجينات (الإضافات) من `.py` إلى `.so` على جهاز الإنيجما 2 (Vu+, Octagon, Dreambox, ...)
مع **نسخة احتياطية تلقائية** وسكربت **استرجاع** حتى لا تخسر الكود الأصلي أبداً.

---

## 📁 محتويات المجلد

| الملف | الوظيفة |
|---|---|
| `compile_tool.sh` | الأداة الرئيسية: تثبّت الأدوات، تنسخ احتياطياً، تجمّع `.py` → `.so` |
| `restore_backup.sh` | يسترجع ملفات `.py` الأصلية من النسخة الاحتياطية في أي وقت |
| `quick_compile.sh` | مشغّل سريع يركض على الجهاز نفسه (يحمّل الأدوات من قناتك على GitHub) |
| `connect_enigma.bat` | مساعد ويندوز: يفتح تيلنت ويعطيك الأوامر الجاهزة |
| `upload_to_github.ps1` | يرفع الملفات الجديدة إلى قناتك على GitHub تلقائياً (يحتاج توكن) |

---

## ✨ ما الجديد في الإصدار v4

1. **نسخة احتياطية تلقائية** قبل التجميع → تُحفظ كل ملفات `.py` الأصلية في مجلد `.py_backup` داخل البلوجين (مع قائمة `manifest.txt`). في v3 كانت تُحذف نهائياً!
2. **استرجاع بضغطة واحدة**: `restore_backup.sh` يعيد الملفات الأصلية ويحذف ملفات `.so` المُجمّعة (حتى الموجودة في مجلدات فرعية).
3. **دعم Python 2.7** للأجهزة والصور القديمة (mipsel) إضافة لدعم Python 3 — يكشف الإصدار تلقائياً ويختار `language_level` الصحيح (2 أو 3).
4. **`__init__.py` مستثنى دائماً** من التجميع ومن الحذف — والبلوجين يبقى يُحمَّل بشكل طبيعي.
5. **سجل أخطاء مفصل**: كل المخرجات تُكتب في `compile_log.txt` داخل مجلد البلوجين.
6. **إصلاح التموضع**: على بعض الصور يضع المترجم ملفات `.so` في مجلد مكرر (مثل `XPortal/XPortal/`)، الأداة تنقلها تلقائياً بجانب الملفات الأصلية وتمحو المجلدات الفارغة.
7. **ما الجديد في v4.2**: اختيار ذكي لإصدار Cython — الصور بنظام **Python 3.12+ (مثل 3.14 في صور Vu+ الجديدة)** تثبّت Cython الأحدث تلقائياً (لأن 0.29 يولّد كود C غير متوافق مع 3.14)، بينما تبقى الصور القديمة (Python 2.7 / 3.5) على 0.29.36.
8. **ما الجديد في v4.3**: إصلاح شامل لخطأ `cannot find -latomic_asneeded` عند الربط — الأداة الآن تزيل العلم الشبح `-latomic_asneeded` من **كل** متغيرات sysconfig (بما فيها `LIBS` و `SYSLIBS` حيث يختبئ في الصور الجديدة)، مع تثبيت `libatomic1` وإنشاء ملف ربط وسيط كخطة احتياطية.
9. **ما الجديد في v4.4**: تصحيح sysconfigdata على القرص (حتى العمليات الجديدة لا ترى العلم الشبح) + تشخيص يُظهر المصدر الحقيقي للعلم (env / sysconfig / أداة المُجمِّع).
10. **ما الجديد في v4.5**: اكتشاف أن `gcc` غالباً **غير موجود في المسار** على هذه الصور (المُجمِّع الفعلي هو `arm-oe-linux-gnueabi-gcc`) — حل نهائي لخطأ `-latomic_asneeded`: الأداة تنشئ **سكربت ربط** (`INPUT ( libatomic.so.* )`) يوجّه الاسم الشبح للمكتبة الحقيقية المثبّتة، **بدون الحاجة لأي مُجمِّع إطلاقاً**.
11. **ما الجديد في v4.6**: إصلاح خطأ `ld: cannot find ...ui/channel_list.o` — البناء المتوازي في setuptools يُفقد ملفات `.o` الوسيطة على الأجهزة البطيئة/منخفضة الذاكرة، فالأداة الآن تُجبر **البناء التسلسلي** (ملف واحد تلو الآخر) + تُضيف سطر **فحص مساحة القرص** في بداية التجميع وعند الفشل (سطور `[disk]`) لتسهيل التشخيص.
12. **ما الجديد في v4.7**: إصلاح خطأ `error: could not create 'Plugins/Extensions/XPortal/api/...so': No such file or directory` — setuptools عند `--inplace` يبني مسار النسخ على افتراض أن مجلد العمل هو جذر `Plugins` فينتج مساراً مكرراً خاطئاً داخل البلوجين. الحل: **إلغاء `--inplace` كلياً** — الوحدات تُبنى داخل `build/` ثم **Step 5** ينقل كل `.so` بجانب ملفه الأصلي (نفس آلية إصلاح التموضع الحالية)، مع **فحص تحقّق** نهائي في اللوج لكل ملف ليس له `.so`.
13. **ما الجديد في v4.8 (الاستئناف الذكي)**: إذا فشل التجميع عند أي وحدة، تُنقذ الوحدات المنجزة تلقائياً (تُنقل `.so` بجانب ملفاتها) وتُطبع `Saved N already-built module(s) - the next run resumes from here`. عند إعادة التشغيل **يُتخطّى المنجز** (`Resuming: skipping N file(s)`) ويُكمَل من حيث توقف — **لا إعادة من الأول**. يعمل أيضاً بعد نجاح كامل: إن عدّلت ملف `.py` واحداً فقط يُعاد تجميع ذلك الملف وحده.

## 🚀 طريقة التجميع

### الطريقة 1 — من الكمبيوتر (ويندوز)
1. شغّل `connect_enigma.bat`
2. أدخل عنوان الجهاز `192.168.0.161` ثم اختر `1` (تجميع)
3. أدخل اسم البلوجين (مثل `XPortal`)
4. افتح التيلنت والصق الأمر الجاهز الذي سيظهر

### الطريقة 2 — من الجهاز مباشرة (تيلنت)
```bash
telnet 192.168.0.161
# دخول: root + Enter
```

ثم حمّل الأداة وشغّلها:
```bash
wget --no-check-certificate https://raw.githubusercontent.com/azroukarim/sos/refs/heads/main/compile_tool.sh -O /tmp/compile_tool.sh && /bin/sh /tmp/compile_tool.sh
```

أو عبر `quick_compile.sh`:
```bash
wget --no-check-certificate https://raw.githubusercontent.com/azroukarim/sos/refs/heads/main/quick_compile.sh -O /tmp/quick_compile.sh && /bin/sh /tmp/quick_compile.sh compile XPortal
```

الأداة ستسألك عن اسم البلوجين ثم تنفّذ تلقائياً:
1. تثبيت `gcc` + أدوات بايثون + `Cython 0.29.36`
2. أخذ نسخة احتياطية من كل `.py`
3. التجميع إلى `.so` في نفس الأماكن
4. حذف ملفات `.py` المترجمة فقط (مع بقاء `__init__.py`)
5. عرض الملخص وطلب إعادة تشغيل الإنيجما

## ♻️ الاسترجاع (إعادة الكود الأصلي)

في أي وقت بعد التجميع:

```bash
cd /usr/lib/enigma2/python/Plugins/Extensions/XPortal
/bin/sh restore_backup.sh
```

أو مباشرة:
```bash
/bin/sh restore_backup.sh /usr/lib/enigma2/python/Plugins/Extensions/XPortal
```

أو من القناة عبر `quick_compile.sh`:
```bash
/bin/sh quick_compile.sh restore XPortal
```

ماذا يفعل؟
- يعيد كل ملف `.py` من `.py_backup`
- يحذف ملفات `.so` المُجمّعة المقابلة
- يحذف مجلد النسخة الاحتياطية وسكربت الاسترجاع نفسه
- يُعاد تشغيل الإنيجما يدوياً: `killall -9 enigma2`

## 🐍 الأجهزة القديمة (Python 2.7)

الأداة تكتشف الوضع تلقائياً:
- وُجد `python3` → يجمّع بـ `language_level=3`
- لم يُوجد (صور قديمة mipsel) → يجمّع بـ `language_level=2` ويستعمل `python-dev`

> ملاحظة: يبقى `Cython 0.29.36` هو المثبَّت أولاً لأنه يدعم النسختين معاً. إذا فشل تثبيته على صورة قديمة جداً، جرّب: `opkg install python-cython`

## 📄 ملف اللوج

كل شيء يُسجَّل في: `البلوجين/compile_log.txt`
- قائمة الملفات المكتشفة
- مخرجات التجميع كاملة
- سبب الفشل إن وُجد
- قائمة ملفات `.so` الناتجة

إذا فشل التجميع: **لا يُحذف أي ملف `.py`** والنسخة الاحتياطية تبقى في مكانها.

## ⚠️ مهم جداً: رفع الملفات الجديدة إلى قناتك على GitHub

`quick_compile.sh` و `connect_enigma.bat` يحمّلان الأدوات من رابطك:
`https://raw.githubusercontent.com/azroukarim/sos/refs/heads/main/`

بعد التعديلات، **ارفع هذين الملفين الجديدين إلى نفس المجلد في قناتك**:
- `compile_tool.sh` (النسخة v4.1)
- `restore_backup.sh`

وإلا سيبقى الجهاز يحمّل النسخة القديمة من القناة.

### 🔑 طريقة الرفع التلقائي (من ويندوز) — المُوصى بها
1. أنشئ توكن من GitHub:
   `Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic)`،
   فعّل فقط خيار **`repo`** ثم انسخ التوكن (يبدأ بـ `ghp_...`)
2. شغّل في مجلد `enigma2-cython-compiler`:
   ```powershell
   powershell -ExecutionPolicy Bypass -File upload_to_github.ps1
   ```
3. الصق التوكن عند الطلب — السكربت يرفع الملفات الثلاثة تلقائياً (يستبدل القديم ويضيف الجديد) ويعرض روابط التحميل الصحيحة.

### 🖥️ طريقة الرفع اليدوي (بدون توكن)
1. افتح `https://github.com/azroukarim/sos`
2. اضغط `Add file → Upload files`
3. ارفع `restore_backup.sh` و `quick_compile.sh` (ملفات جديدة)
4. افتح `compile_tool.sh` القديم → اضغط أيقونة ✏️ (تعديل) → الصق محتوى النسخة v4.1 → `Commit changes`

### ℹ️ لماذا يرد الرابط 404؟
- رابط المجلد العاري `.../main/` **يرد 404 دائماً** — `raw.githubusercontent.com` لا يعرض قوائم المجلدات، بل **الملفات الفردية فقط**:
  - ✅ `https://raw.githubusercontent.com/azroukarim/sos/main/compile_tool.sh`
  - ✅ `https://raw.githubusercontent.com/azroukarim/sos/main/restore_backup.sh` (بعد رفعه)
- إذا رجع ملف محدد 404 → الملف غير موجود بعد في القناة (رفعه أولاً).

## 🔧 حل المشاكل الشائعة

| المشكلة | الحل |
|---|---|
| `No module named Cython` | تأكد من اتصال الإنترنت، أو ثبّت يدوياً: `pip3 install cython` |
| خطأ `_PyLong_AsByteArray ... expected 6, have 5` أو أي خطأ `too few arguments` أثناء `gcc` | الصورة عندك **Python 3.12+** (3.14) وتحتاج سيفتون حديثاً، والأداة v4.2 تكتشف هذا تلقائياً وتثبّت الأحدث. إذا أردت يدوياً: `pip3 install --upgrade --no-cache-dir cython` ثم أعد التجميع |
| خطأ `-latomic_asneeded` عند الربط (`cannot find -latomic_asneeded`) | صُحّح نهائياً في v4.5: الأداة تنشئ **سكربت ربط** `INPUT ( libatomic.so.* )` يوجّه الاسم الشبح للمكتبة الحقيقية (بلا حاجة لمُجمِّع، لأن `gcc` ليس في المسار على هذه الصور). يدوياً: شغّل `ls -l /usr/lib/libatomic*` ثم الصق الاسم في `echo 'INPUT ( libatomic.so.X )' > /usr/lib/libatomic_asneeded.so` |
| خطأ `ld: cannot find .../X.o: No such file or directory` (يظهر بعد ناجاح ترجمة الوحدة مباشرة) | صُحّح في v4.6: هذا خلل البناء **المتوازي** في setuptools على الأجهزة البطيئة — الأداة تُجبر البناء التسلسلي تلقائياً. انتبه أيضاً لسطور `[disk]` في اللوج: إذا كانت المساحة الحرة قليلة احذف ملفات مؤقتة أو صدّر المسار الحقيقي للـ `.c` خارج الفلاش قبل إعادة التجميع |
| خطأ `error: could not create '.../api/...so': No such file or directory` (يظهر بعد نجاح تجميع كل الوحدات) | صُحّح في v4.7: خطأ نسخة `--inplace` — setuptools يبني مسار النسخ على افتراض خاطئ (جذر `Plugins`). الأداة الآن تلغي `--inplace` وتنقل كل `.so` بجانب ملفه الأصلي تلقائياً مع فحص تحقّق نهائي في اللوج |
| فشل التجميع في منتصف الطريق وأريد المتابعة دون إعادة كل شيء | صُحّح في v4.8: أعِد نفس الأمر فقط — الوحدات المنجزة تُنقذ وتُتخطّى تلقائياً (`Relocated` + `Resuming: skipping N` في اللوج) ويُكمَل الباقي. ضمان: النسخة الاحتياطية `.py_backup` تبقى سليمة دائماً |
| خطأ `unichr` | على بايثون 3 تُصحَّح تلقائياً (`_chr = unichr` → `_chr = chr`) |
| البلوجين لا يظهر بعد التجميع | تأكد أن `__init__.py` ما زال موجوداً، وأن ملفات `.so` بجانب الملفات الأصلية، ثم أعد تشغيل الإنيجما |
| أريد الكود الأصلي back | شغّل `restore_backup.sh` كما في القسم أعلاه |
| البلوجين يستعمل `exec/eval/__file__` أو انعكاس `inspect` | هذه الخصائص لا تترجم جيداً بـ Cython — أبقِ ملف `.py` لها أو عدّل الكود |
| تحذيرات `Unreachable code` أثناء التجميع | مجرد تحذيرات طبيعية — تجاهلها، التجميع يستمر |

## 🧪 كيف اشتغل؟ (للمتطفلين على التفاصيل)

- `Cython` يحوّل `.py` → `.c` → ثم `gcc` يترجمها إلى `.so`
- التجميع على **الجهاز نفسه** يضمن تطابق المعمارية (mipsel/arm) ونسخة بايثون تلقائياً — لا حاجة لـ cross-compiler أو Docker
- ملفات `.so` الناتجة أسرع قليلاً وأصعب في فك الشيفرة
- نفس النمط الذي يستعمله الإنيجما 2 نفسه مع مكتبته `enigma.so`
